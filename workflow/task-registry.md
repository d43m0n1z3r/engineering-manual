# Task and Gate Registry

[`task-registry.json`](task-registry.json) is the machine-readable task graph for
orchestration. It is generated by [`scripts/build_task_registry.py`](../scripts/build_task_registry.py)
from the task cards plus curated orchestration metadata; regenerate it with
`python3 scripts/build_task_registry.py` and verify freshness with `--check` or
`scripts/check_manual.py`.

## Field semantics

| Field | Meaning |
|---|---|
| `depends_on` | Hard task dependencies. A task is READY only when all listed tasks are VERIFIED. |
| `gate_required` | Gates that must be approved before the task may be claimed. |
| `feeds_gates` | Gates the task's verified output is submitted to; gate entry rules still apply. |
| `role` / `roles` | Primary accountable agent role and involved agent roles (slugs under `agents/roles/`). |
| `skills` | Part 5 category numbers; `skill_categories` maps them to files and titles. |
| `human_approval` | Human approval required in addition to any gate, when stated by the manual. |
| `validation`, `outputs`, `card`, `source` | Copied from the task card for convenience; the card remains authoritative. |

The `gates` section mirrors `workflow/gates/G*.md` entry criteria and approval
authorities for convenience. The registry operationalizes the dependency table
in `workflow/state-machine/dependencies.md`; a project Orchestrator may refine it
per project but MUST NOT weaken gates, evidence, or authorization requirements.
